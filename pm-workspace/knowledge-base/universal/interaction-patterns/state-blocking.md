> 状态阻断引导通则：当用户试图操作一个当前不可用的功能/对象时，阻断不是终点，引导才是——好的阻断设计让用户知道"为什么不行"和"可以怎么办"。

scope: universal
来源: framework generalized interaction pattern
提炼时间: 2026-04

---

## 适用范围

任何产品中，当用户遇到"此操作当前不可执行"的场景，包括：
- 规格/商品不可购买
- 权限不足
- 配额达上限
- 功能未开通
- 条件不满足（如：实名认证未完成）

---

## 核心设计框架：三层信息

好的阻断设计必须向用户传达三层信息：

```
Layer 1 现象层：什么不能做（清晰标注不可用状态）
Layer 2 原因层：为什么不能做（用用户语言解释，不是技术错误码）
Layer 3 出路层：可以怎么办（可操作的下一步）
```

缺少任何一层都是不完整的阻断设计。

---

## 视觉阻断规范

| 场景 | 推荐方式 | 避免方式 |
|------|---------|---------|
| 按钮不可点 | 置灰 + Tooltip 说明原因 | 直接隐藏按钮（用户不知道功能存在） |
| 列表项不可操作 | 置灰沉底 + 标注状态 | 从列表移除（用户以为数据丢失） |
| 表单提交受阻 | 行内错误提示 + 聚焦到问题字段 | 全局 toast 告知失败但不指向问题 |
| 页面级禁止访问 | 专属空状态页 + 引导操作 | 直接 404 或空白页 |

---

## 出路设计原则

出路必须是**可执行的**，不是"联系客服"或"请稍后再试"这类无效引导。

| 阻断原因 | 好的出路 | 差的出路 |
|---------|---------|---------|
| 配额达上限 | "升级套餐" / "管理已有配额" | "当前配额已满" |
| 权限不足 | "联系管理员开通" / 跳转权限申请页 | "您没有权限" |
| 条件不满足 | "完成实名认证后可用" + 跳转认证 | "无法操作" |
| 规格不可购 | "选择其他规格" / "到货提醒" | "该规格不可用" |

---

## 阻断时机

| 时机 | 建议 |
|------|------|
| 用户看到入口时 | 提前置灰，Tooltip 说明原因（用户不会浪费点击） |
| 用户尝试操作时 | 即时反馈，inline 提示（不跳转页面，减少中断感） |
| 系统异步发现阻断 | Toast 提示 + 刷新当前状态（非侵入式） |
| 关键流程节点 | Modal 弹窗，明确说明 + 提供操作选项（高优先级场景） |

---

## 反模式

- ❌ 只阻断不解释 → 用户困惑，产生客诉
- ❌ 隐藏受限入口 → 用户不知道功能存在，但又从其他地方看到过，造成混乱
- ❌ 用技术语言解释（如"权限码不足"）→ 用户看不懂
- ❌ 出路指向无法完成的操作（如：点击"升级"但无升级渠道）→ 比没有出路更差
- ❌ 阻断提示样式与正常提示相同 → 用户不知道这是受限状态
