# inbox/rejected — 不立项需求归档

> 这里存放经过评估后决定"暂不做"或"不做"的需求。  
> 目的：防止同一个需求被反复提起，每次都从零评估。

## 什么样的需求放这里

- 经过 `value-assessment` 得出 **P3 Backlog** 或 **Drop** 结论的需求
- 经过 `pm-orchestrator` 路由判断后主动拒绝立项的需求
- 用户明确说"这个先不做"并附有理由的需求

## 什么样的需求不放这里

- 还没评估过的需求（放 `inbox/` 根目录）
- 已立项但被砍掉的功能点（放对应项目的 `PROJECT.md` Out of Scope 里）
- 待观察的需求（继续留在 `inbox/` 根目录，加 `_hold` 后缀标注）

## 命名规则

```
YYYY-MM-DD-{需求简称}-rejected.md
```

## 文件内容模板

```markdown
# {需求名称}

**提出日期**: YYYY-MM-DD
**评估日期**: YYYY-MM-DD
**评估结论**: 暂不做 / 不做

## 需求描述
{一句话描述这个需求是什么}

## 拒绝原因
{1-2句，说清主要原因（价值低 / 时机不对 / 成本过高 / 方向不符）}

## 重新评估的触发条件
{什么情况下这个需求值得重新看：无 / 指定条件}

## 原始材料
{如有，链接到 inbox/ 中的原始文件}
```

## 使用提示

- 每次有新需求进来时，先搜一下 `inbox/rejected/`，看有没有类似的历史记录
- `routing-policy.md` 中有不立项路径的完整说明
