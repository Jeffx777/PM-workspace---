# 异步批量导入交互通则
# B端外部数据大批量导入动作：默认异步队列+记录表查询，不阻塞主线程

## 适用场景
适用于 B 端系统中，需向第三方接口发起大批量的数据导入/查询/同步请求（如：批量获取第三方平台 APPid、批量导入商品库数据）。

## 核心交互模式
1. **轻量前端输入**：前端仅提供批量的文本域（支持换行符）或简单的文件上传，不做深度的本地字段合法性强校验（仅做基本的判空或格式兜底）。
2. **提交即成功（非阻塞）**：用户点击“确定”或“提交”后，系统直接返回“任务提交成功”的 Toast 提示。**切断前端长轮询或 Loading 等待**，不阻塞用户的后续操作。
3. **后端排队调度**：任务流入后端队列，根据第三方接口的限频规则（Rate Limiting）进行调度消费。
4. **流水分拆与记录（Record List）**：批量请求在底层必须被拆解为单条维度的流水任务。提供「导入记录 / 同步流水」的独立面板，用户可按时间、状态（处理中、成功、失败）筛选，并能直接查看明确的**失败原因**。

## 为什么这么设计？
- **防超时断连**：如果让前端同步等待，一旦外部接口响应慢或处理量大，极易引发 Gateway 504 超时或浏览器卡死。
- **避免木桶效应**：批量请求中只要有一条失败，同步返回很难处理“部分成功、部分失败”的 UI 呈现；打散后独立呈现更为清晰。
- **容错与限频安全**：后端可灵活实施 Exponential Backoff（指数退避重试），规避因为前端集中重试而引发的外部接口熔断。
